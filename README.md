# gen-model-agent

BIOS 774 Project 2: an AI agent that takes a dataset and a free-text objective, decides whether and how to use generative modeling (VAE, GAN, normalizing flow, diffusion), trains and evaluates the chosen model(s) against held-out real data, recommends what the output can and cannot be used for, and writes a PDF report.

The 4-page written report is `docs/report.pdf` (source `docs/report.tex`, built with `tectonic docs/report.tex`).

## Requirements

- **Claude Code**, installed and logged in (`claude` on your `PATH`). The agent runs as a headless Claude Code session. See <https://claude.com/claude-code>. Check with `claude --version`.
- **Python 3.10+** available as `python3`. `run.sh` creates its own `venv/` and installs pinned packages (`requirements.txt`, including torch 2.14.0) on the first run. It never installs anything outside `venv/`.
- **Internet access** on the first run, for `pip` and the two dataset downloads (PBMC 3k, about 6 MB; PathMNIST, about 200 MB). Both downloads are checked against the md5 in each dataset's `DATA_DESCRIPTION.md`.
- Developed on macOS (Apple M4, 16 GB RAM). No GPU required: tabular models run on CPU, and image models use Apple MPS or CUDA when available, otherwise CPU.

## Reproduce the two generated reports from a fresh clone

```bash
git clone https://github.com/yanruoz/gen-model-agent.git
cd gen-model-agent

# Optional check (about 1 minute plus the first-time install): creates venv/, downloads PBMC,
# and runs one short headless Claude Code call; prints SMOKE PASS.
./run.sh pbmc --smoke

# Dataset 1: PBMC 3k single-cell RNA-seq (about 10 minutes)
./run.sh pbmc "Learn a low-dimensional representation and generate realistic synthetic cells for sharing" --report-number 1

# Dataset 2: PathMNIST histology images (about 40 minutes, or about 70 if the critique leads to a retrain)
./run.sh pathmnist "Generate realistic tissue images of each class that could replace the real data for training a tissue classifier" --report-number 2
```

Each command prints one progress line per agent step and ends with `DONE: reports/<dataset>/generated_report_<N>.pdf`. It exits with an error if the report was not produced.

**Keep the machine awake during runs.** A PathMNIST run can last over an hour, and the headless session dies if the computer sleeps. On macOS, `run.sh` prevents idle and system sleep with `caffeinate`, but it can't stop sleep from closing the lid: keep the lid open and the power plugged in. On Linux, disable suspend for the duration.

**Usage.** Each run is a headless Claude Code session (`claude -p`), which counts against your Claude Code plan (per the Claude Code docs, `claude -p` usage on subscription plans draws from a separate monthly Agent SDK credit). If a run stops with a usage-limit or session-limit message, rerun the same command after the limit resets.

Other objectives work the same way. For example, these were used to check that the agent chooses differently by objective:

```bash
./run.sh pbmc "Flag unusual cells that may be doublets or low-quality captures"      # anomaly detection
./run.sh pbmc "Recover gene expression values lost to dropout"                        # imputation
./run.sh pathmnist "Balance the rarest tissue class to improve a classifier"         # class balancing
```

An objective the pipeline cannot test on that data (for example uncertainty quantification) is declined or adapted, with the reason in the report.

The agent's decisions (model choice, hyperparameters, evaluation) depend on the model's reasoning, so a rerun can choose slightly differently. Given the same plan, the numbers are deterministic: every training, sampling, and evaluation step is seeded.

### Where things go

| Path | Contents |
|---|---|
| `reports/<dataset>/generated_report_<N>.pdf` | The generated report (the deliverable) |
| `outputs/<dataset>/` | Every intermediate artifact: `profile.json`, `objective.json`, `plan.json`, `run_log.json`, `metrics/`, `runs/` (training curves), `figures/`, `samples/` (synthetic data), `recommendation.json`, `findings.md`, and `agent_transcript.jsonl` (the full agent session) |
| `data/<dataset>/` | `DATA_DESCRIPTION.md` (tracked) and the downloaded data file (not tracked) |

`outputs/`, `data/` files, and checkpoints are git-ignored and regenerated by the commands above.

### Options

```
./run.sh <dataset> "<objective>" [--report-number N] [--budget-min M] [--use-api-key]
```

- `--report-number`: defaults to the next free number across `reports/`.
- `--budget-min`: total training budget the agent plans within (default 30). A model that doesn't fit is recorded as not run, never silently dropped.
- Any folder `data/<name>/` with a `DATA_DESCRIPTION.md` (and optional `## Loading` section) can be run the same way; nothing in the pipeline is specific to these two datasets.

## Authentication

Pipeline runs use your **Claude Code login** by default. `run.sh` always drops any `ANTHROPIC_API_KEY` inherited from your shell, and it ignores the key in `.env` unless you opt in:

```bash
cp .env.example .env    # then set ANTHROPIC_API_KEY in .env
./run.sh pbmc "<objective>" --use-api-key
```

With `--use-api-key`, usage is billed to that API key instead of your Claude Code plan.

## How it works

`run.sh` checks prerequisites, sets up `venv/`, downloads the dataset if needed, and starts `claude -p` with `AGENT.md` as the agent's instructions. The agent then:

1. profiles the data (`scripts/profiler.py`);
2. turns the objective into `objective.json`, including whether to model at all (`validate_objective.py` enforces the data checks, e.g. no class balancing without labels);
3. writes `plan.json`: split, preprocessing, models, hyperparameters, each with a dataset-specific reason (`validate_plan.py` checks the model can serve the task, seeds, and budget);
4. runs `scripts/run_plan.py`: preprocess, then train, generate, and evaluate each model and seed, then draw the figures;
5. writes `recommendation.json` (`validate_recommendation.py` checks every cited number and rejects privacy claims);
6. writes `findings.md` and builds the PDF with `scripts/report.py`, which refuses numbers that don't trace to an artifact.

Decision rules live in `.claude/skills/*/SKILL.md`; all computation is in `scripts/`. The agent decides and writes; it never computes a number itself.

## Permissions

There are two settings files:

- `.claude/settings.json`: dev settings for interactive Claude Code sessions in this repo. Allows web search/fetch and `git add/commit/status/diff`. Denies `git push` (including force-push) and reading `.env`.
- `.claude/pipeline-settings.json`: passed to `claude -p` by `run.sh`. The agent can run only `venv/bin/python scripts/*`, read the repo, write inside `outputs/`, and call the critic subagent. It can't write to `data/` or `reports/` (only `scripts/report.py` writes reports), and it can't run git, use the web, install packages, or read `.env`. Anything not allowed is denied without a prompt.

Pipeline runs use `--setting-sources local`. They don't load the dev settings, `CLAUDE.md` (dev notes), or your user-level Claude Code settings, so the agent sees only `AGENT.md`, `pipeline-settings.json`, and the skill files it reads. As a backup, `pipeline-settings.json` also denies everything the dev file allows (checked by `tests/test_settings.py`).
